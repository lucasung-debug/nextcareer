# 다음경력 (NextCareer)

> 전역 간부가 당연하게 수행해온 일상 업무에서 실제 책임과 역량의 근거를 찾아,
> 민간 채용자가 이해하고 평가할 수 있는 **경력기술서**로 바꿉니다.

원티드 AI Championship 2026 출품작.

**바로 체험:** [다음경력 웹 데모](https://nextcareer-five.vercel.app/)

설치·로그인·API 키 발급 없이 웹에서 체험합니다. `가상 사례 먼저 보기`는 유료 AI 요청 없이 면담 39단계, 원문 근거 확인, Word 생성, 직군 탐색을 보여줍니다. 아래 설치 안내는 소스코드를 직접 실행할 개발자를 위한 안내입니다.

---

## 문제

전역(예정) 간부·부사관은 몇 년간 실무를 했지만, 민간 이력서 앞에서 막힙니다.

- 부대에서 쓰던 말이 민간에서 통하지 않습니다.
- "특별한 성과"가 없으면 쓸 게 없다고 느낍니다. 하지만 **반복해서 해온 일이 곧 경력**입니다.
- 그래서 많은 경우 AI에게 "그럴듯하게" 써달라고 맡기고, 검증할 수 없는 문장이 남습니다.

이 서비스는 반대로 갑니다. **지어내지 않고, 실제로 말한 것만 남깁니다.**

## 핵심 원칙

1. **질문은 코드가 정한다.** AI가 즉흥적으로 묻지 않습니다.
   `planner.ts`가 지금 무엇이 비어 있는지 보고 다음 질문을 결정합니다.
2. **AI는 추출만 한다.** AI 역할은 사용자의 답변에서 사실을 뽑고, 원문 인용을 붙이는 것뿐입니다.
3. **근거 없는 문장은 화면에 올라가지 않는다.** `grounding.ts`를 통과해야만 카드가 됩니다.
4. **확인한 것만 문서에 실린다.** 사용자가 "확인"한 항목만 경력기술서에 들어갑니다.
5. **모르면 모른다고 쓴다.** 결과가 없으면 `미확인`으로 남기고 추정하지 않습니다.

## 지어내기를 막는 3중 검증

`src/lib/career/grounding.ts`

| 단계 | 검사 | 예시 |
| --- | --- | --- |
| 1. 인용 검증 | AI가 붙인 인용이 사용자 메시지에 **글자 그대로** 있는가 | 없으면 항목 폐기 |
| 2. 수치 검증 | 문장의 숫자가 인용에 **같은 토큰**으로 있는가 | 근거 `1.5배` → 주장 `5배` 폐기 |
| 3. 표현 검증 | 성과·서열·직급 환산 표현을 사용자가 직접 말했는가 | `무사고`, `총괄`, `과장급` 등 |

수치 검증에 부분 문자열 비교를 쓰면 `15명`이 `5명` 주장을 통과시킵니다.
그래서 숫자를 토큰으로 잘라 **정확히 일치**할 때만 통과시킵니다.

## 면담 구조

```
복무 기본정보   군별 · 신분 · 전역(예정) 사유
      ↓
보직            부대명 · 보직명 · 재직기간 · 이동 사유      ← 여러 개
      ↓
경험            한 보직에서 여러 업무                      ← 보직당 최대 4개
      ↓
심층 질문       수행 업무 → 책임 범위 → 직접 한 행동
                → 판단 기준 → 함께 일한 대상 → 사용한 도구
                → 어려웠던 점 → 결과(마지막, 없어도 됨)
      ↓
경력기술서      확인된 사실만 · Word(.docx) 내려받기
```

- 같은 항목은 **최대 2번**까지만 묻고 넘어갑니다. 몰아붙이지 않습니다.
- "기억이 안 나요 / 넘어갈게요"를 그대로 받아들이고, 건너뛴 항목은 사실로 저장하지 않습니다.
- `직접 한 행동`은 절차가 드러날 때까지 한 번 더 캐묻습니다.

## 확인한 경험에서 채용 탐색까지

- 대화와 경력 패널은 독립적으로 스크롤됩니다. 모바일에서는 대화 / 경력·채용 화면을 전환합니다.
- 경력 패널은 **01 근거 확인 → 02 경력기술서 → 03 채용 탐색** 순서로 이동합니다.
- 직군 제안은 본인이 확인한 항목만 사용합니다. 보직명, 경험 제목, 미확인 항목, 참고 AI 해석은 분류 근거가 아닙니다.
- 사전 정의 업무 토큰과 겹치는 문장을 그대로 보여주고 원문 근거를 열 수 있습니다. 부정·전달만 한 문장을 보수적으로 제외합니다. 정규식 기반 최소안이므로 완전한 의미 이해나 적합도 판정은 아닙니다.
- 공고 본문을 수집·저장·재배포하지 않습니다. 원티드 검색 링크만 열며, 실제 담당 업무·필수 자격·근무 조건은 원티드에서 직접 확인합니다. 검색 결과가 없을 수도 있습니다.
- 검색 URL에는 미리 정한 일반 업무 키워드만 들어갑니다. 이름·부대명·대화 원문을 보내지 않습니다.

### 화면 디자인 근거

- **Refero / Attio:** 흑백 중심 위계, 감사 인사에 한정한 Newsreader 세리프, 10px 주요 버튼. [원본 스타일](https://attio.com)
- **Refero / Cal.com:** 회색 바탕 위 흰 작업 패널과 절제된 표면 깊이. [원본 스타일](https://cal.com)
- **Refero / Metaview:** 대화 원문과 요약 문서를 나란히 검토하는 분할 작업 구조. [화면 근거](https://refero.design/pages/f711cee8-7d0e-4a3a-a044-39f8dc183e85)
- **TypeUI / Minimal:** 4px 단위 간격 리듬, 컨트롤 상태, 접근성 우선 원칙만 반영. 인디고·아이보리 팔레트와 별도 폰트는 혼합하지 않았습니다. [참고 문서](https://www.typeui.sh/design-skills/minimal)
- 파란색은 근거를 여는 기능에만 사용합니다. 본문은 한국어 가독성을 위해 Pretendard를 유지합니다.

## 검색·공유·서비스 식별

- 서비스 표시 이름은 **다음경력 / NextCareer**, 소스 저장소·내부 패키지는 **nextcareer**입니다.
- 제출 링크는 **https://nextcareer-five.vercel.app/** 로 유지합니다. 기존 링크를 깨뜨리는 도메인 변경은 하지 않습니다.
- React·Vite 앱입니다. 빌드 시 첫 화면과 이용 FAQ를 같은 React 컴포넌트로 미리 렌더링하고, 브라우저에서는 해당 HTML을 이어서 활성화합니다. 별도 Next.js나 데이터베이스는 사용하지 않습니다.
- HTML에 한국어 설명, 대표 URL(canonical), Open Graph·Twitter 공유 카드, WebSite·WebApplication 구조화 데이터를 넣습니다. 평가·평점·가격·성과를 지어내어 마크업하지 않습니다.
- robots.txt와 홈페이지 1개 URL의 sitemap.xml을 제공합니다. /api/의 크롤링은 제한하고 응답에는 noindex를 붙입니다. robots.txt는 보안 장치가 아니며 실제 입력 검사는 서버에서 합니다.
- 검색/AI 답변에 노출되거나 높은 순위를 얻는다는 보장은 없습니다. Search Console 등록·색인 요청은 이 코드 변경과 별개의 작업입니다.
- 공식 근거: [Google AI 기능](https://developers.google.com/search/docs/appearance/ai-features), [JavaScript SEO](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics), [OpenAI 크롤러](https://platform.openai.com/docs/bots).

## 데이터 취급

- 대화는 **브라우저 메모리에만** 있습니다. 데이터베이스가 없습니다.
- 경력기술서 Word 파일은 **브라우저에서** 만듭니다. 문서 내용을 서버로 보내지 않습니다.
- Gemini는 **유료 구간**을 씁니다. 무료 구간은 입력이 모델 학습과 사람 검수에 쓰이므로
  개인 경력을 다루는 이 서비스에 맞지 않습니다.
  ([Gemini API 약관](https://ai.google.dev/gemini-api/terms))
- 주민등록번호·군번·전화번호·주소·좌표·총기 및 탄약 수량·장비 식별번호·보안 절차는
  AI로 보내기 전에 차단합니다. (`pii.ts`)
- 부대명은 물어보되, 문서에 실제 명칭을 쓸지 일반 표기(`○○사단`)로 쓸지 사용자가 고릅니다.

```

  planner.ts          다음 질문 결정          ← 면담 로직의 핵심

  gemini.ts           Gemini 호출
  client.ts           브라우저 API 요청 · 60초 대기 제한
  rateLimit.ts        인스턴스 내 요청 제한 (최선 노력)
  pii.ts              민감정보 차단 · 부대명 일반화
  period.ts           재직기간 파서
  jobBridge.ts        확인된 근거 → 직군·원티드 검색 링크
  careerDocument.ts   경력기술서 구성
  docxBuilder.ts      Word 생성
  sample.ts           가상 사례 (실제 인물 아님)
```

## 서버 안전장치

- 전송될 모든 메시지와 경험 제목·보직 문맥을 서버에서 다시 검사합니다. 마지막 답변만 검사하지 않습니다.
- 서버의 Gemini 요청은 50초에 중단하고, 클라이언트는 최대 60초를 기다립니다. 플랫폼 함수 제한은 60초입니다.
- API 응답은 no-store이며 본문·API 키를 로그에 남기지 않습니다. 정적 응답에는 nosniff와 Referrer-Policy를 지정합니다.
- 메모리 기반 요청 제한은 인스턴스 간 공유되는 강제 지출 한도가 아닙니다. 운영자는 Google Cloud의 사용량·할당량을 별도로 관리해야 합니다.

## 실행

```bash
npm install
cp .env.example .env.local   # GEMINI_API_KEY 입력
npm test                      # 단위 테스트
npm run build                 # Vite + 첫 화면 미리 렌더링 + 결과 검증
npm run preview               # 완성 빌드 확인
```

실제 Gemini 호출 테스트 (요금 발생):

```bash
LIVE=1 npx vitest run gemini.live
```
